# Decisions

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-10-30 | New payroll routes **coexist** with the legacy `payroll.generation.*` / `payroll.maintenance.*` routes, using different names and URLs. Legacy files are not edited, imported or deleted. | CLAUDE.md forbids deleting functionality without instruction; the legacy code is broken but routed. |
| D2 | 2026-10-30 | No DTR engine is built. Time quantities enter payroll through a `TimeInputProvider` contract; the shipped provider reads approved `payroll_time_inputs`. | No existing code calculates late/undertime/absence/OT; building a DTR belongs to the Time module and is out of scope. A future DTR plugs in as a provider. |
| D3 | 2026-10-30 | Work country/subdivision is stored on `employment_assignments` (plus optional `location_id`) instead of adding columns to `locations`. | Avoids changing the Administration module; jurisdiction is an assignment attribute anyway. |
| D4 | 2026-10-30 | New `legal_entities` table, optionally linked to `organization_general_information`. | Multi-entity support without overloading the single existing row. |
| D5 | 2026-10-30 | Payroll run approval is permission-based with enforced separation of duties (calculator ≠ reviewer ≠ approver; calculator ≠ finalizer), not `ApprovalChainResolver`. | The resolver walks a subject employee's supervisor chain; a payroll run has no subject employee. |
| D6 | 2026-10-30 | Money: bcmath strings via `Decimal` (scale 10), `decimal(19,4)` amounts, `decimal(19,8)` rates, `decimal(12,4)` quantities; precision from `currencies.minor_units`; one rounding per line. | Skill `payroll-calculation-engine`; no new dependency needed. |
| D7 | 2026-10-30 | Non-statutory rounding mode is a pay-group setting (default `half_up`, chosen by the company). Statutory lines use the rounding declared by the rule version, falling back to the pay-group mode only if the rule declares none. | Rounding for company-paid items is company policy, statutory rounding is law. |
| D8 | 2026-10-30 | No real statutory values are seeded or hard-coded. Rules are entered through the Statutory Rules screen with source metadata and verified by a different user. Only verified versions can be used in a run that is finalized. | Skill `payroll-compliance-localization`; assignment section 6 ("do not invent"). |
| D9 | 2026-10-30 | Payroll reports reuse the Reports module (`ReportRegistry` new `payroll` category, `report.payroll`), scoped by legal entity inside each report query. | Reuses existing web/Excel/PDF/print pipeline instead of a second export stack. |
| D10 | 2026-10-30 | Fix the `success` flash gap once in `HandleInertiaRequests` + layout snackbar. | CLAUDE.md "known gap"; payroll actions need feedback; one deliberate, cross-cutting fix instead of per-page workarounds. |
| D11 | 2026-10-30 | Default role grants: `payroll` role operates payroll (prepare/calculate/review); `hr_director` approves/finalizes/verifies rules; `superadmin` all; everyone gets `payslip.view_own`. `payroll.scope.all` granted to superadmin, hr_director and payroll; others need explicit entity assignments. | Separation of duties by default; single-entity installs work without extra setup; companies can re-scope. |
| D12 | 2026-10-30 | Supported pay frequencies: weekly, biweekly, semi_monthly, monthly. Compensation bases: annual, monthly, semi_monthly, biweekly, weekly, daily, hourly. | Assignment section 5; `job_offers.salary_frequency` lacks biweekly so payroll has its own list. |
| D13 | 2026-10-30 | Daily rate for salaried bases = annualized amount ÷ pay group `annual_working_days`; hourly = daily ÷ `hours_per_day`. Both are required pay-group settings with no default. | Divisors are company/localization policy; no global 8-hour or 261/313-day assumption. |
| D14 | 2026-10-30 | Run types: `regular`, `supplemental`, `reversal`. "Adjustment" is an approved `payroll_adjustments` row applied in a regular or supplemental run. | Covers adjustments, off-cycle and reversals with one lifecycle. |
| D15 | 2026-10-30 | New model names avoid every class the legacy payroll code imports but doesn't exist (`PayrollCalendar`, `PayrollDeduction`, `PayrollAccountType`, `PayrollEmployee*`, `PayrollProjectFund`, `SalaryGrade`, `SalaryMatrix`, `SalarySchedule`, `SalaryStep`). The `payroll_calendars` table's model is `PayGroupCalendar`. | The legacy payroll routes have no `can:` middleware; creating a model they import would let any logged-in user reach the new payroll tables through them. |
| D16 | 2026-10-30 | A rule version is selected by the date its own `applies_by` names (resolver evaluates each candidate), not by a date the localization code picks. | The issuance decides whether pay date or period dates govern; this keeps it data, not code. |
| D17 | 2026-10-30 | Earnings are rounded before the localization computes statutory bases. | Bases must equal what the payslip shows. |
| D18 | 2026-10-30 | PH premium categories carry the full compounded multiplier (DOLE Handbook guide tables), with explicit night/holiday/rest-day combination categories. | The Handbook compounds factors; a single additive "night differential" on the regular rate would under-pay combined hours. |
| D19 | 2026-10-30 | PH monthly contributions in non-monthly pay groups follow a required company setting (`ph.contribution_schedule`: `last_period` or `split`). | Splitting is company policy, not law (skill `payroll-country-philippines`). |
| D10a | 2026-10-30 | D10 refined: `HandleInertiaRequests` now shares `flash.success` (additive), but it is displayed by the payroll page mixin (`resources/js/mixins/payrollPage.js`), not globally. | 87 existing pages already call `showToast()` in their own success handlers; a global flash toast would show duplicates across other modules. A global display can be switched on once those pages stop toasting themselves. |
| A1 | 2026-10-30 | The `feature/hikvision-api` sample is used as reference, not merged; the adapter is reimplemented with Laravel's HTTP client (digest auth) instead of adding `shaykhnazar/hikvision-isapi`. | Avoids a new dependency (CLAUDE.md) and the sample's unauthenticated test route, hard-coded employee and payload logging. |
| A2 | 2026-10-30 | Legacy `employee_attendance_logs` / `employee_biometric_ids` and the pages reading them stay unchanged; new pipeline uses new tables and can ingest legacy rows (`legacy_table` source). | Backward compatibility; the writer of the legacy table is outside this repo. Repointing Time Logs / My Attendance to the new tables is a follow-up decision (BLOCKERS A-B1). |
| A3 | 2026-10-30 | Device user IDs are scoped per device (`biometric_enrollments` unique per device among active rows), not global. | Biometric IDs are device-specific; the legacy table's global uniqueness can't model multiple devices. |
| A4 | 2026-10-30 | Rotating/multiple shifts are date-specific roster overrides on top of the Time module's weekly schedules. | Reuse the existing schedule model; no second schedule engine. |
| A5 | 2026-10-30 | Holidays gain nullable `country_code`/`subdivision_code`; null keeps today's "applies everywhere" behavior. | Jurisdiction-aware holidays without breaking existing holiday pages. |
| A6 | 2026-10-30 | Payroll reads attendance only through approved `attendance_period_summaries`; pay groups opt in via `time_source = attendance` (default `manual_inputs` keeps current behavior). The localization maps attendance buckets to premium categories (`MapsAttendanceToPremiums`). | No calculation duplicated in payroll; no country rule in the attendance engine; backward compatible. |
| A7 | 2026-10-30 | ZKTeco: only the HTTP PUSH/ADMS receiver (ATTLOG) is implemented; the TCP 4370 / Windows SDK protocol is not. | Only PUSH has (partial) public vendor documentation; TCP is undocumented/reverse-engineered. |
| A8 | 2026-10-30 | Device push endpoints live in a new stateless route file `routes/Attendance/device.php` (no session/CSRF, no `/api` prefix) registered in `RouteServiceProvider`; ZKTeco devices require the fixed `/iclock/*` paths. | Devices can't send CSRF tokens; ADMS paths are fixed by firmware. |
| A9 | 2026-10-30 | Instants (`attendance_events.occurred_at`, scheduled/first/last times) use a UTC cast (`App\Casts\UtcDateTime`). | The default `datetime` cast reads values in the app timezone (`Asia/Manila`), which would shift UTC instants by 8 hours. |
| A10 | 2026-10-30 | Late and undertime are measured in scheduled working time (the unpaid break is excluded). | Leaving at 12:00 on an 08–17 shift with a 12–13 break is 4 h short, not 5. |
| A11 | 2026-10-30 | `ReportRegistry::catalogFor()` also checks each report's own `permission()`. | Device sync history needs `attendance.device.view`, stricter than its category; existing reports unchanged (their permission is the category's). |
| A12 | 2026-10-30 | Payroll integration is event-driven (`PayrollRunFinalized`) and through optional contracts, not direct calls into attendance. | Keeps payroll independent of attendance; manual-input pay groups behave exactly as before. |
| A13 | 2026-10-30 | PH: holiday-on-rest-day and double-holiday premium categories are not derived from attendance; they are entered as time inputs. | The HRMS can't distinguish them reliably from one holiday record per date. |
| A14 | 2026-10-30 | No biometric templates/images are stored; Hikvision names/card numbers and ZKTeco template uploads are excluded. | Data minimization (RA 10173); identity references are enough for attendance. |
| A15 | 2026-10-31 | The attendance module replaces every legacy attendance workflow; `employee_attendance_logs` stays as an unchanged read-only archive, read only by the one-time `attendance:import-legacy-logs`. | User decision: no parallel attendance systems or second source of truth. Dropping the table waits for writer shutdown and a retention decision. |
| A16 | 2026-10-31 | The legacy import is a dry-run-first artisan command requiring an explicit device timezone; rows without an `employee_biometric_ids` mapping stay in the archive. No device records are created. | No invented timezones, devices or employee mappings; repeatable without duplicates. |
| A17 | 2026-10-31 | Old route names `time.my-attendance.index` and `time.time-logs.index` are kept as redirects; `time.my-attendance.export`, `attendance.logs.import-legacy` and the `attendance-summary` report are removed. | Bookmarks and old links keep working without exposing obsolete functionality. |
| A18 | 2026-10-31 | `attendance.update`, `attendance.delete`, `attendance.reprocess` removed (seeder + migration; `down()` restores the former default grants). | Never checked by code; raw events are append-only and corrections go through approved adjustments. |
| A19 | 2026-10-31 | A connector tied to a legal entity/location may only serve devices of that entity/location. | Organization isolation for hosted deployments. |
| A20 | 2026-10-31 | Unrouted legacy files that still mention the removed models (`LeaveApplicationFormRequest`, legacy `HrManagement\EmployeeController` biometric field and its resources/`JobForm.vue`) were left unchanged. | Dead code in other modules (CLAUDE.md legacy list); editing them is outside this task. |
| A21 | 2026-10-31 | Supersedes A15-A17: the legacy attendance tables are dropped (`2026_10_31_000006_remove_legacy_attendance`), no historical import, no redirects. | Owner confirmed all legacy rows are test/demo data and authorized complete removal. |
| A22 | 2026-10-31 | Legacy create migrations stay; a new migration drops the tables. Pending attendance migrations (never committed or deployed) are edited in place; payroll migrations untouched. | Never rewrite migrations that ran elsewhere; keep the pending history minimal (one cleanup migration). |
| A23 | 2026-10-31 | Supersedes A20: the two unrouted legacy files were cleaned (biometric field removed from the legacy employee edit; the unused leave request reads `attendance_events`) without removing their other functionality. | Owner asked for remaining legacy references to be resolved. |

| A24 | 2026-10-31 | Pull sync is incremental: the cursor stores the end of the last completed window (`pulled_to`); each run starts there minus `overlap_minutes` (default 10, env `ATTENDANCE_SYNC_OVERLAP_MINUTES`) plus measured clock drift. Scheduled every minute; an hourly `--lookback=1440` pass catches late-stored events. | The old cursor (last *accepted* event − 24 h) didn't advance for unmapped-only or quiet periods, so windows grew without bound; a 24 h re-read every minute is wasteful. Failed pulls don't advance the cursor, so outages are recovered. |
| A25 | 2026-10-31 | Hikvision adapter accepts XML answers for deviceInfo/time. | The DS-K1T321MFX (V4.61.0) answered deviceInfo without a JSON section despite `?format=json`. |
| A26 | 2026-10-31 | Near-real-time Hikvision ingestion uses ISAPI alertStream through `attendance:listen` (ext-curl, digest), handing events to `DeviceSyncService::receivePush` (source `device_push`, trigger `stream`); polling stays as recovery. HTTP host notification was not configured. | alertStream works on the device without changing device settings; same dedupe key as polling. |
| A27 | 2026-10-31 | Replayed alertStream records (`currentEvent: false`) older than the polling cursor minus the overlap are skipped. | The device replays its whole undelivered log on first connect; history must not be imported by streaming. |
| A28 | 2026-10-31 | HTTP push now applies the same major/minor filter as polling and streaming (shared `notificationEvent()`). | One classification rule; unconfigured codes (e.g. 75) are not stored as punches. |
| A29 | 2026-10-31 | HTTP host push is accepted for polled Hikvision devices too (token + source-IP check) and goes through `DeviceStreamService::handle(..., 'push')`, which skips any pushed event behind the polling cursor. | Push must coexist with polling/stream; a newly configured host receives the device's stored log, which must not be imported. |
| A30 | 2026-10-31 | The push receiver acknowledges with ISAPI `ResponseStatus` XML (explicit Content-Length) only after the event is stored, recognized as a duplicate or deliberately skipped; failures return 500 so the device retries. A terminable middleware logs the status actually sent; Debugbar is disabled on the route. | Device behavior: any prompt 2xx advances its queue, non-2xx is retried ~1/s. |
| A31 | 2026-10-31 | HTTP Listening is the primary Hikvision path; scheduled pulls skip devices with a healthy push channel (heartbeat/event within 120 s) except an hourly catch-up; the 24 h re-read runs daily instead of hourly; pulls are ingested page by page with one duplicate query per page. | Push delivers in ~1 s with device-side store-and-forward; routine polling re-read the same history (measured cost in the integration guide). Pull-only devices keep minute-level catch-up. |
